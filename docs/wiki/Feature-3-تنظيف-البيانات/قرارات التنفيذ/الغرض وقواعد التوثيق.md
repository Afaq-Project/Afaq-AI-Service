# الغرض من سجل قرارات التنفيذ

## الغرض

يوثق هذا القسم القرارات التقنية والهندسية التشغيلية التي يتخذها agents أثناء تنفيذ feature: عند تعديل الكود، أو الاختبارات، أو إعدادات الأدوات، أو التوثيق، أو أي عمل مرتبط بالتنفيذ. يسجل القرار وما نُفذ فعلياً والأسباب والبدائل التي جرى النظر فيها ثم استبعادها.

## الفرق بين هذا السجل وADR

- يوثق **ADR (Architecture Decision Record)** قراراً معمارياً تأسيسياً مهماً يُتخذ في مرحلة التصميم، مثل اختيار نمط معماري أو تقنية رئيسية، مع سياقه وعواقبه.
- يوثق **سجل قرارات التنفيذ** قرارات العمل اليومية أثناء بناء feature، مثل اختيار طريقة تنفيذ، تعديل fixture، تقسيم service، أو تغيير أسلوب الاختبار.
- لا يُستخدم هذا السجل بديلاً عن ADR، ولا تُكرر فيه القرارات المعمارية عالية المستوى التي مكانها ADR. إذا كشف التنفيذ عن قرار معماري أساسي جديد، يُقترح توثيقه في ADR مناسب، ويُشار إليه هنا عند الحاجة.

## من المسؤول ومتى؟

الـ agents الذين ينفذون الكود أو الاختبارات أو التوثيق أو المهام المرتبطة مسؤولون عن تحديث سجل feature الذي يعملون عليه. يُوثق القرار عند اتخاذه أو فور تنفيذ الإجراء، لا في نهاية العمل فقط. إذا لم يوجد قرار أو بديل ذو قيمة، فلا يلزم تسجيل تحديث شكلي.

## المعلومات المطلوبة لكل سجل

- **المعرّف والعنوان:** رقم تسلسلي قصير وعنوان واضح.
- **من اتخذ القرار:** اسم agent أو دوره، مثل `Codex` أو `Test agent`، مع اسم الشخص عند مشاركته في القرار.
- **التاريخ:** بصيغة `YYYY-MM-DD`.
- **السياق:** المهمة أو المشكلة التي استدعت القرار.
- **القرار والإجراء:** ما تقرر وما نُفذ، مع مسارات الملفات ذات الصلة عند اللزوم.
- **البدائل المستبعدة:** البدائل التي نوقشت وسبب استبعاد كل منها. اذكر `لا توجد بدائل جوهرية` إن لم تُدرس بدائل.
- **النتيجة أو الأثر:** أثر القرار على التنفيذ أو الاختبارات أو الصيانة، وأي متابعة لازمة.

## قواعد الكتابة

- تُكتب جميع محتويات هذا القسم باللغة العربية، مع إبقاء المصطلحات التقنية وأسماء الملفات والمعرّفات وواجهات API باللغة الإنجليزية.
- اذكر الوقائع التي حدثت فعلاً، وافصلها عن المقترحات أو الخيارات التي لم تُنفذ.
- لا تسجل الأسرار أو بيانات الاعتماد أو محتوى حساساً.
