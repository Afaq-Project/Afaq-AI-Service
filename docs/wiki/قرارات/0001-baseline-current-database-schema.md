# ADR 0001: إنشاء خط أساس بمigrations رسمية للمخطط الحالي لقاعدة البيانات

- **الحالة:** مقبول
- **التاريخ:** 2026-11-15
- **أصحاب القرار:** القائمون على صيانة Afaq-AI-Service

## السياق

تطور مخطط قاعدة البيانات الذي يستخدمه النظام الحالي بشكل كبير مقارنة بالمخطط الموصوف في ملفات Prisma migration الملتزم بها. تصف migrations الموجودة النظام السابق، بينما تحتوي قاعدة البيانات المحلية `afaq_test` على جداول scraping الحالية، ومنها `raw_grant_details` و`cleaned_opportunities`. ولا تحتوي قاعدة البيانات على جدول `_prisma_migrations`، لذلك لا يمكن التحقق من سجل migrations الذي أنشأها. استخدم المشروع مزامنة المخطط عبر Prisma (`prisma db push`) بدلاً من سلسلة migrations رسمية لهذه التغييرات.

قاعدة الإنتاج المحددة في `.env` خارج نطاق هذا القرار، ويجب ألا تتأثر بأعمال المخطط المحلية.

## القرار

إنشاء migration baseline رسمية باستخدام Prisma تعكس المخطط الحالي المعتمد، ثم إدارة جميع تغييرات المخطط اللاحقة عبر migrations محفوظة في المستودع. يجب التوفيق بين baseline وسجل migrations القديم ومخطط Prisma الحالي قبل تطبيقها على أي قاعدة بيانات تحتوي بيانات. يُمنع تطبيق migration القديمة الأولى أو baseline جديدة مباشرة وبلا تحقق على قاعدة بيانات قائمة.

بالنسبة إلى Feature 3، يُحدد أولاً عقد بيانات التنظيف، ثم يُتحقق من ملاءمة `CleanedOpportunity` له. وبعد إنشاء baseline، تُعبّر migrations عن أي تغييرات مخطط مطلوبة.

## المبررات

- لا يصف سجل migrations المحفوظ في المستودع المخطط الذي يستخدمه scraping حالياً.
- تحتوي قاعدة الاختبار على الجداول الحالية لكنها تفتقر إلى سجل Prisma، ما يمنع تتبع حالة migrations بشكل موثوق.
- تجعل baseline وmigrations التزايدية تغييرات المخطط قابلة للمراجعة وإعادة الإنشاء والنشر في بيئات الاختبار والإنتاج.
- يمنع التوفيق والتحقق قبل التطبيق تعارض إنشاء الجداول وفقدان البيانات العرضي.

## النتائج

### فوائد

- يصبح تطور المخطط صريحاً ومرقماً وقابلاً للمراجعة.
- يمكن إنشاء البيئات الجديدة باستمرار من سجل migrations المحفوظ.
- يمكن مقارنة حالة قاعدة البيانات بسلسلة migrations مرجعية.

### التكاليف والمخاطر

- يجب التوفيق بين سجل migrations القديم والمخطط الحالي؛ وقد يتطلب ذلك baseline معدة بعناية بدلاً من إعادة تشغيل migrations القديمة.
- تحتاج قواعد البيانات القائمة إلى إجراء آمن لاعتماد baseline. إنشاء ملفات migrations وحده لا يسجلها باعتبارها مطبقة على قاعدة قائمة.
- يجب التحقق من baseline على قاعدة بيانات مؤقتة قبل استخدامها مع بيانات نريد الاحتفاظ بها.

## النطاق والضوابط

- ينطبق القرار على مخطط التطبيق الحالي وتغييرات المخطط المستقبلية.
- لا يجيز القرار أو يتطلب تغيير قاعدة الإنتاج ضمن أعمال تصميم baseline.
- يجب عدم تمرير بيانات اعتماد الإنتاج من `.env` إلى أوامر migrations المحلية؛ تُستخدم قاعدة الاختبار المخصصة للتحقق.
